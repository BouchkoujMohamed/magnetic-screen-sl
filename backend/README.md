# Order backend — Google Sheets via Apps Script

Orders from the landing page go to a Google Apps Script web app. The script adds each order to the **Orders** tab of the spreadsheet set in `SPREADSHEET_ID` (currently `1uOJrcKl4MAHL4etcjf43StEsfjuotsAZmSzkZMc6Sq0`). Your Google login and spreadsheet permissions never appear in the website code. The website only knows the web app's public URL, and that URL can do one thing: add an order that passes validation.

## Spreadsheet layout (your design is kept as it is)

Tab **`Orders`** (gid 0):

| Row | Content | Script |
|---|---|---|
| 1 | Decorative title | Never touched |
| 2 | `Order ID \| Name \| phone \| adresse \| Quantité \| Price` | Read only, to check the layout |
| 3+ | Orders | Fills columns **A–F** only |

| Order ID | Name | phone | adresse | Quantité | Price |
|---|---|---|---|---|---|
| MS-261120-0007 | Aminata Kamara | +23276123456 | 12 Wilkinson Road, Lumley, Freetown | 2 | 1200 |

- **Order ID:** generated by the script as `MS-YYMMDD-NNNN`, or `TEST-YYMMDD-NNNN` for test orders. The prefix is the only way to tell test orders from real ones. Before using an ID, the script checks it isn't already in `Orders` or `_order_log`.
- **phone:** always stored as text in the `+232XXXXXXXX` format. If the cell is already Plain text, it's written as is. Otherwise a hidden leading apostrophe stops Sheets from turning it into a number. The cell's format isn't changed either way.
- **Quantité and Price:** numbers, `1`/`2` and `660`/`1200` (SLE). The script sets the price; the browser can't change it.

**Your design is never changed.** The script writes **values only**. It never sets fonts, colours, borders or number formats, and never touches rows 1–2 or columns G and beyond.

**Where the next order goes:** the first row after the **last filled Order ID** whose A–F cells are all empty and hold no formula. Things that don't matter:
- formatting, banding or colours extending far down
- checkboxes or formulas in other columns

Rows with anything in A–F, such as a hand-typed note or a formula that shows nothing, are skipped and never overwritten.

**Header check:** if row 2 doesn't hold the 6 headers, nothing is written and the customer sees "Sorry, we can't take orders right now because of a technical problem…". The check ignores capitals, extra spaces and how "é" was typed.

Hidden tab **`_order_log`**, created by `setup()`. It's the only thing the script ever creates:

`Order ID | Date & Time | Request Key | Mode | Package | Currency | Orders Row | State`

To see it, use **View → Hidden sheets**. Don't edit it: it's what blocks duplicates and recovers interrupted saves.

## How a save works (consistency)

Everything below runs while holding one script lock, so simultaneous orders are handled one at a time and two orders can never get the same ID.

1. **Already handled?** The script looks for the request key, first in its 6-hour memory, then permanently in `_order_log`. If the order was already saved, it returns the same Order ID and adds nothing.
2. **Reserve:** for a new order, the script generates a unique ID and adds it to `_order_log` as **`pending`**.
3. **Write:** it fills A–F of the next free row in `Orders`, then reads the row back to confirm it.
4. **Confirm:** it marks the log entry **`saved`**, together with the row number.

If something fails partway, the customer sees an error. When the same request is retried:
- **Reserved, but the row wasn't written:** the retry writes it, with the same Order ID.
- **Row written, but the log wasn't updated:** the retry finds the row and returns it. No second row is added.

## Setup and deployment (in your Google account)

Never share your password or any security code with anyone. **Don't run `goLive`.**

1. **Check the spreadsheet:** open the new spreadsheet and confirm the tab is named exactly **`Orders`** and that row 2 holds the 6 headers.
2. **Create the script:** in that spreadsheet, go to **Extensions → Apps Script**. This creates a script project attached to the new spreadsheet. Replace everything in `Code.gs` with this folder's [`Code.gs`](Code.gs), then click **💾 Save**.
3. **Run `setup`:** choose `setup` in the function menu, click **▶ Run**, and allow access when Google asks. The log should read:
   `OK — version 2026-11-19-header-row-2. Spreadsheet "…" (…1uOJrcKl4MAHL4etcjf43StEsfjuotsAZmSzkZMc6Sq0…). Tab "Orders" (gid 0): headers found in row 2, 0 existing orders, next order goes to row 3. Hidden log tab "_order_log": 0 entries. Live orders enabled: false`
   - **The only change in the spreadsheet is a new hidden tab, `_order_log`.** `Orders` isn't modified.
   - **If setup stops with "Row 2 of "Orders" must hold…",** the message shows what it found. Nothing was changed.
4. **Deploy:** go to **Deploy → New deployment → ⚙️ → Web app**:
   - Description: `Orders SL v1`
   - Execute as: **Me**
   - Who has access: **Anyone**

   Click **Deploy** and copy the **Web app URL**.
5. **Check it:** open the URL. It should show `"version":"2026-11-19-header-row-2"` and `"live":false`.
6. **Point the website at it:** the URL goes into `ORDER_ENDPOINT` in `script.js`, only after step 5 checks out.

Older deployments, attached to previous spreadsheets, can be archived under **Deploy → Manage deployments → Archive** once the new one is confirmed.

## Test mode, then live

Real orders need **two switches**, so they can't start by accident.

| | Website (`script.js`) | Apps Script |
|---|---|---|
| Test (default) | `ORDER_MODE = "test"`. Orders are marked as tests, and the page shows a "Test mode" notice. | Saves test orders with a `TEST-` Order ID. Refuses real orders. |
| Live | `ORDER_MODE = "live"` | Run **`goLive()`** once in the editor. Test orders are still accepted, so the site never fails while it switches. |
| Live, test orders closed | `ORDER_MODE = "live"` | After the live site is confirmed, run **`closeTestOrders()`**. The endpoint then refuses `test:true` orders (`test_closed`), so nobody can add `TEST-` rows to the live table. A stale test-mode page shows "This page has been updated. Please refresh…". |

`closeTestOrders()` refuses to run unless live orders are on, because otherwise no orders at all would be accepted. To stop real orders at any time without redeploying, run **`goTestOnly()`**. It also re-opens test orders. The health check shows both switches: `"live"` and `"testOrders"`.

## Checking where orders go

- **Version:** opening the `/exec` URL shows the deployed `version`.
- **Destination:** `setup()` logs the spreadsheet, the tab's gid, the number of existing orders and the next row to be used.
- **Test orders:** the reply includes `"tab"` and `"row"`.

## If you change Code.gs later

Go to **Deploy → Manage deployments → ✏️ Edit**, set **Version: New version**, then **Deploy**. The URL stays the same. To roll back, select a previous version.

## Protections built in

- **Server checks:** name 2–80 characters, `+232` plus 8 digits (first digit 2–9), address 3–200 characters, quantity 1 or 2, and a currency and total matching the current SLE price. If any check fails, nothing is written and the page highlights the field.
- **Duplicates:** the button is locked while sending, the request key is checked against the 6-hour memory, and it's also checked permanently in `_order_log`.
- **Concurrency:** one script lock covers the duplicate checks, Order ID generation and both writes.
- **Confirmed before success:** the script reads the row back. The customer sees "Thank you" only after that, and an error message otherwise.
- **Spam filter:** a hidden field that bots fill in gets the request rejected.
- **Formula protection:** customer text starting with `=`, `+`, `-` or `@` is stored as plain text.

## Limits to know

- **Public URL:** anyone who finds it can send fake orders that pass validation. The confirmation call is your filter. If spam becomes a problem, a rate limit or CAPTCHA can be added.
- **Speed:** Apps Script usually replies in 1–5 seconds. The page waits up to 25 seconds before showing an error.
- **Usage limits:** Google limits Apps Script per day and allows about 30 requests at once. A normal landing page stays far below that.

## Data retention (12 months)

The privacy notice promises that customers' **name, phone number and address are kept for 12 months from the order date**, unless the law requires longer. After that they are deleted. The order number, quantity and price may be kept for sales records.

**Where personal data is kept:** only in columns B–D (`Name`, `phone`, `adresse`) of the `Orders` tab. The hidden `_order_log`, the script's memory and its logs, and the Meta Pixel never receive name, phone or address. The order date comes from the Order ID (`MS-YYMMDD-NNNN`).

**Monthly check (read-only):** in Apps Script, run **`retentionReport`**. The log lists:
- the rows past 12 months that still hold personal details
- rows with personal details but no recognisable Order ID, to check by hand

It changes nothing.

**Clearing expired rows:** for each listed row, clear only **B, C and D** (Name, phone, adresse). Keep the Order ID, Quantité and Price, and don't delete the row, so the sheet's design and later rows stay in place. An automatic clean-up function can be added later if you prefer.

**Version history:** Google Sheets keeps old versions of a file, and clearing cells doesn't remove the values from **File → Version history**. To make sure deleted details are really gone, once a year:
1. **File → Make a copy.** The copy has no version history.
2. Point `SPREADSHEET_ID` in `Code.gs` to the copy and publish a new version.
3. Delete the old file and empty the Drive trash.

Also delete any downloaded exports and WhatsApp messages older than 12 months that contain customer details.
